# API surface

The rustdoc reference is generated by CI on release; this page is the tour.
Every signature mirrors `src/lib.rs` — if they diverge, `src/lib.rs` wins and
this page is a bug to report.

!!! info "Pre-release behavior"
    The wire layer is implemented and verified end-to-end against IRIS
    Community 2025.3 (protocol 69, live suite green 2026-10-15). The
    signatures below mirror `src/lib.rs`; plaintext TCP only — no TLS yet.

## Connection

| Item | Shape | Notes |
|---|---|---|
| `ConnectionOptions::new(host, ns, user, pass)` | builder | port defaults to **1972**; `.port(p)` overrides; `Debug` renders `password` as `"***"`, never plaintext |
| `connect(opts) -> Result<Connection>` | sync | TCP + greeting + handshake (`HS`) + auth/namespace attach (`CN`) |
| `conn.close() -> Result<()>` | sync | authoritative `DC` disconnect (go `Disconnect` / py `close` parity); idempotent — `Drop` afterwards sends nothing; `Drop` alone stays best-effort (it cannot report an IO error), so prefer `close()` |
| `conn.server_version() -> Result<String>` | | banner via `%SYSTEM.Version.GetVersion` |

A connection is one ordered request/reply stream with no interior
synchronization: hand ownership (or `&mut`) to one thread at a time, or
open a connection per thread. After an IO error or timeout the reply
stream is no longer dependable — the recovery path is `close()` (or
`drop`) plus a fresh `connect()`; there is no reconnect-in-place API, and
no pooling helper ships with the crate.

## Globals (M-level)

| Item | Shape | Notes |
|---|---|---|
| `global!(Name)` / `global!(Name(sub, ...))` | macro | builds a `Global` reference; subscripts stringify |
| `conn.get::<T>(&g)` / `set(&g, v)` / `kill(&g)` | | typed via `value::Value`; names/subscripts are **not** validated client-side — the server's `<SYNTAX>`/`<UNDEFINED>` surfaces as `Error::Server`, as in both reference drivers |
| `conn.next(&mut g) -> Option<String>` | cursor | collation-order subscript walk: sibling cursor at M `$ORDER` level (go `GlobalNext` parity); compose `next` + recursion for subtree descent |

|---|---|---|

| Item | Shape | Notes |
|---|---|---|

## Errors

`Error` is `#[non_exhaustive]`: `Io`, `Timeout`, `Auth`, `Server{code,
message}`, `Protocol(String)`. Match non-exhaustively — variants are added
as the wire surface grows and a pre-1.0 release may do so without
semver-breaking you. `Server` carries the raw IRIS `$status` / SQLCODE plus
decoded text; for the SQL family the code is the **magnitude** as the wire
reports it (IRIS's negative SQLCODEs travel unsigned; the `OE` message text
names the condition), `Protocol` marks framing desync or an unexpected reply
shape; `Timeout` marks a dial or socket read that exceeded
`ConnectionOptions::timeout_ms` (the option is a dial + per-read socket
timeout, not a per-operation budget; both drivers honor it).

## Design rules (why the surface looks like this)

- No `unsafe` (workspace lint `rust.unsafe_code = "deny"` in `Cargo.toml`),
  no panics on server input; all fallible paths return `Result`.
- No async runtime forced on consumers: sync `std::net` core. The `async`
  feature adds a tokio-backed variant (`irisnative::r#async::Connection`)
  that shares the wire codec and command builders — the request bytes are
  identical to the sync path, pinned by the golden-frame fixtures.
- MSRV **1.85**: the first Rust release with stable edition 2024, which the
  crate is written in.
- Robustness evidence is deterministic pseudo-random property tests
  (hand-rolled xorshift: header and `%List` round-trips plus garbage
  streams, `tests/wire.rs`) and the targeted hostile-server cases
  (garbage before the first reply, accept-then-reset, EOF mid-body,
  stalled reads — `src` unit tests), not a coverage-guided fuzzer; no
  fuzzing harness is shipped.
- IRIS strings are byte-oriented; conversions go through `value::Value` so M
  canonical-number rules can be pinned in one place.
